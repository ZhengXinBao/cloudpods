用户已批准按“腾讯慢任务定位 → AWS Bucket 优化 → 重试治理”的顺序推进。
本文把已批准的方向落实为可独立验证、回滚的第一阶段设计，等待文档审阅。
本阶段不承诺完成全部一小时目标；后续仍需地域发现流水线和有依赖的任务分片。

## 二、子项目 A：腾讯 core 关键路径计时

### 职责

只补齐可定位慢调用的计时，不在原因未明确时盲目并行化。
复用现有 `cloud_sync_trace` 事件和身份传递，不建立第二套日志协议。

主要边界：

- provider 驱动获取、远端 region 获取。
- zone 获取、规格同步、每 zone 的 storage/host 同步、快照同步、镜像同步。
- 对定位出的长阶段，再加入 SDK 初始化、分页、逐对象远端请求与本地处理的独立计时。

第一补丁按上述粗粒度边界补齐，不向所有对象无上限输出日志。
长阶段开始与结束均可观察，诊断下钻使用有界计数和分段汇总。
父子阶段会重叠，报告禁止直接求和作为总耗时；未覆盖时长必须明确列出。

### 不变量

- 日志只包含阶段名、已有标识、耗时、计数、结果与错误分类。
- 不记录凭证、请求/响应体、完整库存、对象属性或原始错误正文。
- 不为诊断替换传给 SDK/lockman 的原始 context，避免改变锁所有权。
- 保持返回值、panic、取消、所有权和 SDK drain 行为不变。
- 不用心跳代替业务进展；不加“超时即成功”或超时后提前转移执行权。

### 文件边界

- `/opt/tcl/cmp/cloudpods/pkg/compute/models/cloudproviderregions.go`：DoSync 阶段边界。
- `/opt/tcl/cmp/cloudpods/pkg/compute/models/cloudsync.go`：core 内部调用边界。
- `/opt/tcl/cmp/cloudpods/pkg/compute/models/cloudsync_trace.go`：小型诊断封装。
- `/opt/tcl/cmp/cloudpods/pkg/compute/models/cloudsync_trace_test.go`：语义与日志回归。
- `/opt/tcl/cmp/cloudpods/pkg/compute/synctrace/trace_test.go`：已有协议的回归覆盖。

### 验收

失败、取消、panic 都有正确结束状态，日志故障不改变同步结果，原始 context 不变。
测试环境腾讯代表任务的主要耗时必须能归属到具体阶段，再决定其分片方式。
若只增加了计时，交付名称必须是“定位能力”，不能声称腾讯性能已修复。

## 三、子项目 B：AWS Bucket 重复请求与锁内网络调用

### 已确认的问题

`SyncWithCloudBucket` 在更新时调用一次 `GetStats()`，在记录统计变更时再次调用。
AWS 的 `GetStats()` 没有缓存，且内部串行调用 CloudWatch ListMetrics 和指标查询。
Bucket 更新把远端属性读取放在 `db.UpdateWithLock` 回调内，整个集合又串行处理。

### 数据流

完整取得 Bucket 列表 → 获取每个 Bucket 的只读属性快照 → 校验采集结果 →
短锁更新本地字段 → 复用同一统计快照记录变更 → 保持原有后续关联与事件语义。

1. 先实现单对象去重：本次同步的统计只获取一次，写库和事件比较使用同一份结果。
2. 远端属性预取与对象更新分离，UpdateWithLock 回调只能操作已获取的本地值。
3. 缓存仅绑定本次对象同步/批次，禁止跨账号、跨批次的全局无过期缓存。
4. 缺失/失败的统计保持已有值，不能把 `-1` 或未知当作真实零值。
   新对象无法取得统计时，保留可确认的身份及属性并明确报告该资源未完全同步；
   数字字段默认值不能作为统计成功的证据。
5. Bucket 列表取数失败或未完整分页时禁止缺失资源删除；属性采集失败不等于对象消失。
6. 保留完整对账的作用域互斥，不为了缩短对象写锁而直接取消 provider-region 集合锁。
   远端读取移出对象写锁，不宣称所有作用域锁都已移除。

### 有界并发作为独立补丁

先验证单对象快照与 SDK 线程安全，再添加跨 Bucket 的只读预取池。
预取并发默认 1，灰度候选值为 4，不自动对所有云厂商开启；对账结果聚合及写库保持受控。
同一 Bucket 内的非线程安全 getter 不并发，同一对象不重复派发。
实际 API 并发上界还受运行中任务数影响，不能把每任务 4 误报为账号总并发 4；
测试发布前按 provider 槽位和预取并发核算上界，并验证云 API 限额及节流情况。
没有确认可接受限额时保持 1，不能以一小时目标为由跳过限流校验。

取消时停止派发新工作，已经开始且不可取消的 SDK 调用必须真正退出后才能释放所有权。
一次失败不能丢弃其他对象的错误；不输出原始响应作为诊断。

### 文件边界

- `/opt/tcl/cmp/cloudpods/pkg/compute/models/buckets.go`：使用预取值，统计获取去重。
- `/opt/tcl/cmp/cloudpods/pkg/compute/models/cloudsync_bucket_snapshot.go`：新增属性快照和受控预取辅助单元。
- `/opt/tcl/cmp/cloudpods/pkg/compute/models/cloudsync_bucket_snapshot_test.go`：新增计数、错误和并发测试。
- `/opt/tcl/cmp/forks/cloudmux/pkg/multicloud/aws/bucket.go`：仅在需要暴露可验证的取数错误或消除 SDK 内重复查询时修改。
- `/opt/tcl/cmp/forks/cloudmux/pkg/multicloud/aws/bucket_stats_test.go`：新增 AWS 指标取数回归测试。
- `/opt/tcl/cmp/cloudpods/vendor/yunion.io/x/cloudmux/pkg/multicloud/aws/bucket.go`：与上游本地 fork 的实际变更保持一致，不批量更新无关 vendor。

### 验收

同一次已有 Bucket 更新只取一次统计；对象写锁内无远端 getter；失败统计不覆盖旧值。
真实零值仍能更新；statsOnly 路径不增加其他远端取数。
事件只反映实际已写入的统计变化，失败不会生成伪统计变化事件。
预取池覆盖并发上界、取消后停止派发、等待实际退出、每对象只派发一次和 race 检测。
单纯请求数降低不是最终性能验收，还需对比 AWS 代表账号的耗时与数据完整性。

## 四、子项目 C：可解释的重试分类

### 职责

减少确定性失败的重复执行，修复“错误正文包含 timeout 参数就被当作超时”的误判。
优先读取真实错误类型、SDK 错误码和结构化状态，兼容现有包装链。
保持现有原始失败语义和有界诊断，不能用忽略错误提高成功率。

- 授权/认证、权威的地域禁用和确实不支持的调用不自动重试，结果仍为失败。
- timeout 必须有真实超时原因/明确错误码，资源配置里的 timeout 字段不作为依据。
- 限流、暂时不可用、网络超时保持可重试。
- 重复键、缺少关联等不能只凭文本判为永久失败：先区分并发冲突、依赖未完成与确定的数据问题。
- 混合错误保留各类失败信息，不能由截断的第一个消息或 map 遍历顺序决定整体结果。
- 不能证明的错误仍保留为 unknown，不批量改成成功或不可重试。
- 本阶段不降低全局 8 次上限、不改变 60 秒默认间隔来“制造提速”。

错误收集器当前会格式化并截断正文；分类所需的结构化原因必须在格式化之前保留，
同时限制存储大小。原始 error 不直接进入新增 trace 日志。
需要支持的 SDK 接口仍必须修复；只有权威确认不适用的能力才可单列 N/A，且保留已有库存。

### 文件边界

- `/opt/tcl/cmp/cloudpods/pkg/compute/syncqueue/errors.go`：结构化分类与明确兼容策略。
- `/opt/tcl/cmp/cloudpods/pkg/compute/syncqueue/errors_sdk_test.go`：类型、包装、正文误判及优先级测试。
- `/opt/tcl/cmp/cloudpods/pkg/compute/models/cloudsync_errors.go`：分类信息穿过有界错误收集。
- `/opt/tcl/cmp/cloudpods/pkg/compute/models/cloudsync_errors_test.go`：多错误、截断、收集边界回归。
- `/opt/tcl/cmp/cloudpods/pkg/compute/syncqueue/queue_test.go`：失败/重试终态与租约回归。

### 验收

已确认永久错误只执行一次并报告失败，暂态错误仍按现有上限重试。
正文中的 timeout 配置不误分类；包装和截断不能隐藏确定的错误分类。
租约丢失后不能完成旧任务，无新队列 schema，无既有任务状态回写或清理。
只重试失败分片需要持久化检查点与依赖设计，属于下一阶段，不在本阶段假装已经实现。

## 五、实现、测试与发布次序

每个子项目分别制定可执行计划，以失败测试 → 最小修改 → 回归/竞态测试 → 审查为序。
使用明确文件列表提交，保留工作区既有未跟踪文档和发布证据，不使用 `git add .`。

1. A 先完成观测覆盖；B、C 在各自文件边界内实现，避免把诊断提交和行为变化混在一起。
2. 运行 syncqueue、synctrace、syncworker 和 compute/models 相关测试，构建 region 与 sync-worker。
3. 只有确认隔离的临时数据库/etcd 才运行会写数据的集成测试，禁止连接现网数据库跑测试。
4. 若缺少隔离环境，报告具体跳过项，不把单元测试通过当作全部集成测试通过。
5. 代码与测试通过不代表部署成功。发布前核对镜像摘要、当前活动任务和 drain 能力，
   保留当前镜像和配置作为回滚输入，经 JumpServer 审计发布到既定测试环境。
6. 先分别验证腾讯、AWS、Azure代表账号，再扩展全量；当前文档阶段不触发发布或同步。
7. 测试报告分别记录：取数请求数、API限流、排队/准备时间、各阶段执行时间、尝试次数、
   对象新增/更新/删除及错误数量，检查分页完整性、未知字段保留和关联一致性。

## 六、一小时目标的最终验收与后续依赖

最终以相同 55 个账号、相同资源范围，从批次首个账号启动到最后一个账号完成计算。
必须连续三轮不超过 60 分钟，所有应同步能力均完成，权限/实现缺口不算成功或默认 N/A。
测试数据规模、云 API 限额及资源范围均记录，不能用更小样本替代全量结果。
同步过程新增资源导致分页不一致时，应按云 API 语义补偿核对而不是直接删除本地记录。

设计预算（阶段重叠执行，不是实测预测）：

- 第 10 分钟：准备与地域发现完成，全部任务入队。
- 第 45 分钟：主体和重型资源完成。
- 第 55 分钟：失败分片补偿、完整性核对完成。
- 第 60 分钟：收尾，包含 5 分钟余量。

后续子项目分别是：Azure/其他账号地域能力与发现流水线、基于腾讯实测热点的安全分片、
依赖与完成检查点、分片级重试预算。必须保留所有权、幂等和完整库存的删除保护。
现有权限与服务配置问题需要账号负责人处理，不能由程序性能修改替代。
