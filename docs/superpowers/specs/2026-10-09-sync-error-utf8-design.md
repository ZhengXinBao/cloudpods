# 同步错误文本的 UTF-8 安全性修复（已确认方案）

## 目标和证据

本方案只修复诊断文本在截断后无法写入 MySQL 的问题，不处理其他云权限/能力缺失或一小时性能目标。

2026-10-09 全量批次已经结算：55账号7成功48失败，耗时2小时42分27秒。8个worker分别在完成同一任务 `68c032aa-2e65-4fac-a7f5-8233bf693e8d` 时收到 MySQL 1366（`sync_queue_jobs.last_error` 非法字符串），并按执行所有权保护逻辑退出。

已有本地独立复现调用当前真实 `syncqueue.NewErrorSummary`：输入9000字节合法中文，输出8192字节却不是合法UTF-8。故不能通过删除失败记录、强制成功或禁用worker保护退出处理。

## 方案比较

1. **三边界修复（推荐）**：采集摘要和聚合阶段不再切断UTF-8字符；最终写库再次修复非法字节和限长，覆盖未走聚合器的直接错误。
2. 只在写库前修复：能缓解1366，但前面的摘要仍损坏，其他使用摘要的路径仍不可靠。
3. 改字段为二进制或忽略写库失败：前者扩大schema/API兼容范围，后者损害错误审计和执行所有权；均不采用。

## 修改范围与不变量

- `pkg/compute/models/cloudsync_errors.go` 的 `boundedCloudSyncMessage`：诊断文本保留头尾，沿完整UTF-8字符边界裁剪。把当前“512阈值但可能输出515字节”的实现收紧为真正不超过512字节；已有ASCII超长文本最多比原来少保留3字节，不更改分类。
- `pkg/compute/syncqueue/errors.go` 的 `NewErrorSummary`：输出不超过8192字节，保留现有头尾及省略号策略，保留确定的类别计数。
- `pkg/compute/syncqueue/queue.go` 的 `Complete`：对所有非nil错误的存储文本兜底，仍采用前缀最多8192字节的存储策略；不假设上游一定产生合法文本。
- 共享小型诊断文本帮助函数，避免三处各自实现不一致的UTF-8边界计算；不新增外部依赖、不改依赖fork。
- 对原本非法的UTF-8字节段使用Unicode替换字符供诊断显示，然后按字节预算裁剪；合法且未超预算的文本保持不变。不改变有效Unicode字符，包括中文和四字节emoji。
- 清洗不能只放在超长分支：未超长或恰好8192字节的非法文本也必须处理；替换可能扩容，最终限长以替换后的字节数为准。
- 容量预算始终是字节，不是rune数量；省略号和替换字符计入预算。头尾保留以完整字符为单位，允许少用几个字节，不补填或重排内容。
- 错误分类仍来自原始error/已捕获的类别摘要，不从替换或截断后的文本重新分类。类计数、稳定顺序、error identity/Unwrap等既有契约不变。
- 非nil执行错误仍然记录为失败或按既有策略重试；不转换为成功。nil错误成功路径不变。
- SQL owner谓词、lease、heartbeat、重试次数/间隔、事务和worker保护退出保持原样；其他真实数据库错误仍应返回，不新增兜底吞错/自动重写。
- 不改数据库字符集、字段类型、schema、账号配置、同步范围或并发。
- 仍只保留最多8条采集诊断，不新增共享可变缓冲区；截断后的短字符串不应长期引用巨大的原始字符串底层存储。

## 独立审查和范围限制

只读审查确认三处修复覆盖已证实的队列写库故障。SDK直接错误、Merge保留的原始错误及panic转换错误可能绕过前两处，故Complete兜底不可省。

另有潜在旁路：准备任务的原始错误可经 `pkg/cloudcommon/db/taskman/localtaskworker.go` 的 `Error2TaskData` 写入任务参数，不经过Queue.Complete；项目的 `jsonutils.quoteString` 也不保证修复非法UTF-8。本轮不修改公共JSON库或任务参数通道，该旁路不是此次已证实的触发原因。因此验收结论限定为上述三处及队列last_error写库，不能扩展为“所有任务错误落库都安全”。

## 测试与验收

先加入失败回归，确认当前代码能被测试击中，再实现最小修改。

1. 文本性质：合法UTF-8、字节上限、中文/emoji/ASCII混合、恰好预算与超过预算、前后边界恰好落在多字节字符中、非法字节在开头/中间/末尾、未超长但本身非法、重复处理稳定。
2. 摘要真实路径：typed error → compare.SyncResult/SSyncResultSet.Add → 最终聚合 → collector/Merge；仍非nil，分类及计数不变，头尾诊断仍存在。独立覆盖直接NewErrorSummary和未经过摘要的原始错误。
3. 最终写库：在全新、仅Unix socket、禁用网络的临时MySQL实例和专用数据库中，验证实际Queue.Complete写入和读取。包括原始非法UTF-8、合法长中文被前缀限长、聚合摘要、永久失败、可重试错误以及nil成功。
4. 校验state/error_class、保留的错误文字、attempts及所有权语义，包括stale lease拒绝写入；不能仅证明JSON编码时自动替换成功。原有lease/重试测试必须仍通过，真实SQL错误仍须返回。
5. 运行相关包race、现有错误分类和任务结算测试，并构建region/sync-worker；未提供隔离etcd时明确记录跳过项，不伪报验证通过。
6. 测试数据库不得使用远端10.20.30.43或现有业务库；创建和关闭过程均限定新临时目录及socket。
